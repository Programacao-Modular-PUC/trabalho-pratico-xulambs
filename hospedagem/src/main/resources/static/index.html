🔷 Padrão Singleton — GerenciadorNotificacoes

Garante que exista uma única instância do gerenciador de notificações em toda a aplicação. Qualquer serviço que precise disparar notificações obtém sempre o mesmo objeto via getInstance(), evitando duplicações e centralizando o controle dos observadores registrados.

// Construtor privado — impede new GerenciadorNotificacoes()
private GerenciadorNotificacoes() { }

// Instância estática única
private static GerenciadorNotificacoes instancia;

// Acesso thread-safe via synchronized
public static synchronized GerenciadorNotificacoes getInstance() {
  if (instancia == null)
    instancia = new GerenciadorNotificacoes();
  return instancia;
}

🧩 Demais Padrões de Projeto Implementados
👁️ Observer
Interface NotificacaoObserver com método notificar(evento, aluguel).

Implementações concretas: EmailNotificacao, SmsNotificacao, WhatsAppNotificacao.

O Subject (GerenciadorNotificacoes) mantém lista de observers e despacha para todos ao ocorrer um evento.
📐 Template Method
Classe abstrata RelatorioGerencial define o algoritmo: gerar() → coletarDados() → processar(dados).

Subclasses implementam os passos específicos:
RelatorioFaturamentoMensal
RelatorioTaxaOcupacao
RelatorioClientesFrequentes
⚙️ Strategy (implícito)
Método abstrato calcularDiaria(numHospedes, berco) na classe Quarto.

Cada subtipo implementa a estratégia de precificação:
• Individual: base + adicional por cama extra
• Duplo: base + tipo de cama + taxa berço
• Família: base × hóspedes − desconto progressivo
